# Changes

## 2026-10-17
- **Feature** Assist now logs the recognised text (`Heard: …`) and, if `JOHAN2_HOMEDASH_TRANSCRIPT_URL` is set (e.g. `http://bakkieplus:8767/transcript`), posts it to the HomeDash proxy to show on the wall display. Requires the updated homedash proxy.
- **Improvement** `JOHAN2_MIC_GAIN` default raised from 8 to 16 because the INMP441 signal was weak (local sdkconfig set to 16 too); loud close speech may clip, tune after reading the shown transcripts. Builds and host tests pass; recognition quality is unverified on hardware.
- **Feature** Direct reply playback now decodes MP3 (HA's default TTS format) as well as WAV, using the new pinned dependency `espressif/esp_audio_codec` 2.6.2 (`esp_audio_simple_dec`); format is sniffed from the first bytes, and unknown/undecodable replies still fall back to Music Assistant. The tts task stack is 12 KB. Builds and host tests pass; physical playback is unverified.
- **Fix** Direct reply playback now uses the HA `tts_output.url` (HTTP) instead of the `media-source://` media_id, which previously made it always fall back to Music Assistant.
- **Feature** Spoken replies can now play directly on the device (`JOHAN2_TTS_DIRECT`, default on): a TTS task fetches the HA reply WAV over HTTP, resamples 8-48 kHz mono/stereo 16-bit PCM to 48 kHz stereo and writes it to the DAC, bypassing Music Assistant's announcement overhead. During music it is mixed over a ducked stream (`JOHAN2_TTS_VOLUME`); otherwise it owns the I2S channel, with a mutex coordinating enable/disable with Sendspin. Non-WAV or failed-before-audio replies fall back to the reply media_player if set. Builds and host tests pass; physical playback, mixing and latency are unverified.
- **Fix** `scripts/idf.sh` now sets `safe.bareRepository=all` for its own process only, so a global `safe.bareRepository=explicit` no longer breaks the component manager (`git config --get remote.origin.url` failure). Global git config is untouched.
- **Improvement** Assist runs now send a persistent `conversation_id` (random per boot/idle period, renewed after 300 s without a wake word), so the HA agent keeps context across turns.
- **Improvement** Assist logs now show ms from wake word to reply audio ready, and from there to Music Assistant accepting playback, to locate reply start latency.
- **Fix** Removed the `silence_seconds` Assist input: HA's websocket schema does not accept it (fixed 0.7 s VAD), so it could have caused run rejection.
- **Feature** Added spoken Assist replies through the configured HA TTS engine and Music Assistant: select the Johan2 `media_player` entity in menuconfig, run the pipeline through TTS, and forward its generated audio as an announcement. Added distinct monotonic request IDs, reply acknowledgement/error handling, bounded wait before rearming, URL resolution, and duplicate-playback prevention. The firmware restores normal digital gain before the reply. Door state remains dependent on HA entity exposure and the conversation agent.
- **Validation** Rebuilt with the user-configured local HA token, flashed the attached ESP32-S3 successfully (write hashes verified), and confirmed `HA connected` and `HA authenticated` from filtered serial output. Physical Hey Jarvis recognition, command execution and playback coexistence still need a user test.
- **Validation** Assist firmware passed `./scripts/idf.sh build` with ESP-IDF 6.0.1, host protocol tests and whitespace checks. Not flashed; token authentication, Hey Jarvis recognition, microphone gain and music coexistence remain hardware checks.
- **Feature** Added a Home Assistant Assist WebSocket client for `haos.home:8123`: authenticated 16 kHz microphone streaming to the preferred pipeline with server-side Hey Jarvis detection, command intent handling, reconnection and automatic rearming. Bounded queues isolate capture and Sendspin from networking. Music ducks during commands and the existing music/microphone LED effects remain. Spoken Piper responses and device/area registration are not implemented.
- **Improvement** Added menuconfig settings for the HA endpoint, local token, pipeline ID and microphone gain, explicit pinned direct dependencies for the existing WebSocket/ArduinoJson components, and host tests for authentication, pipeline routing, wake detection, audio boundaries, errors and stale events. Physical Assist/Sendspin coexistence remains to be verified after token setup and flashing.
- **Fix** Restored the coloured source-level music LED effect. Microphone sound temporarily overrides it in white and then fades back to music (or off while idle). Added one-second startup ambient calibration and an adaptive noise gate to suppress continuous white from background noise; physical sensitivity and playback response require verification.
- **Feature** Added an INMP441 input on GPIO15 (SCK), GPIO16 (WS), GPIO17 (SD), with L/R grounded. A dedicated task measures DC-corrected RMS at 16 kHz and drives the RGB LED white with increasing brightness; replaces the music colour effect and works while playback is idle. Separate I2S controllers preserve DAC clocks on GPIO6/5/4. Microphone and LED behaviour require physical verification.
- **Fix** Wait for RMT LED transmission before releasing its stack-backed pixel buffer.
- **Validation** `./scripts/idf.sh build` passed with ESP-IDF 6.0.1; firmware has not been flashed and physical microphone/LED response remains unverified.

## 2026-10-16
- **Feature** Created an ESP-IDF 6.0.1 Sendspin AUX player for ESP32-S3 N16R8 and PCM5102A on GPIO6/5/4, so Music Assistant can send Spotify audio to the existing AUX hardware.
- **Feature** Added Wi-Fi retries, mDNS discovery, volume/mute, DMA playback feedback, and persistent player identity/pairing, so the device can operate as a standalone network audio endpoint.
- **Improvement** Reused HomeDash configuration conventions and added a private Wi-Fi import helper, so local settings can be reused without copying C6-specific hardware settings or publishing credentials.
- **Improvement** Verified the complete firmware build against pinned dependencies; kept credentials local and documented that Music Assistant protocol compatibility and physical audio playback still need hardware validation.
- **Improvement** Checked Music Assistant 2.10.4 provider source for Noise/pairing support and documented setup approval, so the existing server can be tried without an unnecessary upgrade.
- **Fix** Pinned sendspin-cpp v0.8.0 and adapted persistence and stable MAC identity for Music Assistant 2.10.x, so playback uses its supported legacy protocol instead of failing the newer psk_category handshake; user explicitly approved unencrypted LAN audio without pairing. Wi-Fi and existing NVS records are preserved. The prior Noise compatibility assessment above was disproven by hardware logs.
- **Improvement** Refreshed the dependency lock explicitly and verified the legacy firmware with `./scripts/idf.sh build`, so the compiled image uses the intended v0.8.0 client rather than the cached newer dependency; physical playback remains to be tested.
- **Improvement** Firmware 0.2.1 reduces the I2S queue from 30 ms to 10 ms, applies volume in 2.5 ms audio chunks, and polls Sendspin every 2 ms with a 1 kHz RTOS tick, so volume and mute changes have less device-side delay. Spotify-to-AUX playback on 0.2.0 was confirmed working by the user; the lower-latency settings passed `./scripts/idf.sh build` and still require a listening test.
- **Fix** Firmware 0.2.2 restores all audio timing settings from the user-confirmed working 0.2.0 build (6 x 240 DMA frames, 2048-byte write buffer, 100 Hz RTOS tick, original main-loop interval), so the 0.2.1 volume-latency experiment no longer degrades playback. User reported bad audio with 0.2.1; exact cause among the combined changes is not isolated.
- **Feedback** User clarified that volume lag is mainly from the Spotify app; compare the direct Music Assistant player slider with Spotify after restoring audio before changing device buffering again.
- **Validation** Restored firmware 0.2.2 passed `./scripts/idf.sh build` and whitespace checks; playback quality must be confirmed after flashing.
- **Feature** Added an HA blueprint for a back-door-open announcement on a selectable Music Assistant player, using MA's configured TTS engine, a closed-to-open trigger, one-second debounce and ten-second cooldown, so the current ESP32 player can announce door events without firmware changes. The HomeDash sensor ID is prefilled; HA was unreachable, so installation and end-to-end testing remain pending.
- **Fix** Changed the door blueprint to HA `tts.speak` with a selectable HA TTS entity after the installed MA action rejected `message`; removed the unsupported per-call announcement volume and corrected setup instructions. This uses HA TTS, not the MA-only OpenAI TTS plugin.
- **Feature** The onboard addressable RGB LED (GPIO48 by default, `JOHAN2_LED_GPIO`, -1 disables; DevKitC-1 v1.1 uses GPIO38) now pulses with the music's peak level via the built-in RMT driver (WS2812 timing, no new dependency), updated from task context only. Compile-verified only; physical LED behaviour needs a hardware check.
- **Improvement** The music LED is dimmer (capped at about 35 % brightness) and cycles through red, green and blue: it jumps to the next colour on each beat and drifts slowly in between. Compile-checked only; look and brightness need a hardware check.
